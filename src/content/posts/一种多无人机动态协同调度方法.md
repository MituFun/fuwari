代码已在以下仓库中公开，其中 README 为更简略的讲解：

::github{repo="MituFun/drone"}

使用 C++ 实现的无人机配送调度原型。通过 A* 计算航路距离，根据载重、截止时间和电量约束筛选订单，再使用评分函数进行贪心分配；没有接到订单的无人机根据区域评分前往待命。空闲且电量不高于安全值的无人机会原地充电，充满后恢复接单。

## 一、程序流程

```text
读取地图
读取无人机初始信息
循环：
    读取一条新订单
    获取本轮当前时间
    将充电时间已到的无人机恢复为满电和空闲状态
    更新已完成配送或待命移动的无人机位置和状态
    将空闲且电量不高于安全值的无人机设为 TO_CHARGE，记录充满时间
    为 IDLE 无人机分配订单
    为剩余 IDLE 无人机分配待命区域
```

每输入一条订单，触发一轮调度。此前尚未分配的订单也会参与本轮分配。

## 二、数据结构

### 1. 坐标 `$Point`

`x`、`y` 保存二维坐标，用于地图节点、无人机位置和订单的取送货点。

### 2. 订单 `$Order`

| 字段 | 含义 |
| --- | --- |
| `id` | 订单编号，从 1 递增 |
| `pickup` | 取货点坐标 |
| `delivery` | 送达点坐标 |
| `deadLine` | 最晚完成配送的时间 |
| `weight` | 货物重量 |
| `assigned` | 是否已分配 |

`assigned` 表示是否已经分配，不表示是否已经送达。历史订单保留在 `orders` 中。

### 3. 无人机 `$Drone`

| 字段 | 含义 |
| --- | --- |
| `id` | 无人机编号，按输入顺序生成 |
| `location` | 当前记录的位置 |
| `maxWeight` | 最大载重 |
| `battery` | 剩余电量 |
| `status` | 当前状态 |
| `doneTime` | 配送、待命移动或充电的预计结束时间 |
| `taskLocation` | 配送或待命移动的结束位置，充电时位置不变 |

`status` 包括：

| 状态 | 当前代码中的作用 |
| --- | --- |
| `IDLE` | 空闲，可以接单或前往待命区域 |
| `DELIVERY` | 配送中，不参与新订单分配 |
| `TO_SPOT` | 前往待命点，不参与新订单分配 |
| `TO_CHARGE` | 原地充电，不参与订单分配和待命调度，充满后恢复为空闲 |

## 三、主要参数

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `TIME_FOR_PICKUP` | 100 | 取货耗时，秒 |
| `TIME_FOR_OFFLOAD` | 100 | 卸货耗时，秒 |
| `DRONE_SPEED` | 8 | 飞行速度，米/秒 |
| `BATTERY_USED_PER_M` | 0.01 | 每米飞行耗电量 |
| `SAFETY_BATTERY` | 5.0 | 安全电量阈值，也是空闲无人机触发充电的阈值 |
| `BATTERY_CHARGED_PER_S` | 0.01 | 充电每秒增加的电量百分点 |
| `falpha`、`fbeta`、`fgamma` | 0.5、0.2、0.3 | 订单评分权重 |
| `galpha`、`gbeta`、`ggamma` | 0.5、0.3、0.2 | 区域评分权重 |

当前充电逻辑以 100 为满电，因此电量按百分制表示。每米耗电量和每秒充电量均按电量百分点计，输入电量应在 0 到 100 之间。

**评分权重均为暂定值。** 这些数值尚未经过实验验证。

## 四、建图与 A* 路径搜索

### 1. 坐标映射与建图

`getId()` 将坐标映射为整数节点编号：

- `hashId`：坐标到编号。
- `realId`：编号到坐标。
- `g`：图的邻接表，保存相邻节点和边权。

`mapInit()` 读取每条航路的两个端点和长度，分别添加正向、反向边，因此地图为无向带权图。

坐标采用浮点数精确匹配。无人机初始位置、取货点和送达点 **应与已录入的地图节点坐标一致**，程序不会自动寻找最近节点。

### 2. 距离计算

`astar(a,b)` 返回两点之间的航路距离。起终点不在地图中或两点不可达时，返回 `-1`。

优先队列按以下估价值选择待扩展节点：

$$
F(u)=\operatorname{dist}(u)+h(u,t)
$$

其中 `dist[u]` 是当前已发现的起点到节点 `u` 的最小距离，启发函数为欧几里得距离：

$$
h(u,t)=\sqrt{(x_u-x_t)^2+(y_u-y_t)^2}
$$

为保证最短路结果，边权应为非负航路长度，且不小于两个端点的直线距离，使启发函数可以被采纳。

函数只返回距离，没有必要也没有保存或输出路径节点序列。

## 五、订单分配

### 1. 计算候选任务

程序依次遍历 `IDLE` 状态的无人机，只处理 `IDLE` 状态。对于每架无人机，遍历尚未分配的订单。

先检查载重，再通过两次路径搜索计算：

$$
d_1=\operatorname{distance}(\text{无人机位置},\text{取货点})
$$

$$
d_2=\operatorname{distance}(\text{取货点},\text{送达点}),\qquad d=d_1+d_2
$$

任意一段不可达，则跳过该订单。

### 2. 时间与电量检查

任务耗时包括飞行、取货和卸货：

$$
T=\text{TIME\_FOR\_PICKUP}+\frac{d}{\text{DRONE\_SPEED}}+\text{TIME\_FOR\_OFFLOAD}
$$

设订单截止时间为 $D$，本轮当前时间为 $t$，则时间裕量为：

$$
s=D-t-T
$$

`s < 0` 表示立即出发也无法按时完成，跳过该订单。

预计耗电量为：

$$
E=d\times\text{BATTERY\_USED\_PER\_M}
$$

要求：

$$
\text{battery}-E\geq\text{SAFETY\_BATTERY}
$$

当前模型只计算飞行耗电。

### 3. 评分与选择

对满足约束的候选订单计算：

$$
f(i,j)=\frac{\alpha_f}{1+d}+\frac{\beta_f}{1+s}+\frac{\gamma_f}{1+E}
$$

- 距离越短，距离项越高。
- 时间裕量越小，紧迫程度项越高。
- 耗电越少，能耗项越高。

候选项存入 `fs`，包含评分、无人机编号、订单编号和任务耗时。排序后选择评分最高的候选项。评分完全相同时，会优先选择编号较大的订单（这是 `pair` 的性质）。

分配后执行：

1. 将订单标记为已分配。
2. 将无人机状态改为 `DELIVERY`。
3. 设置 `doneTime = now + T`。
4. 设置 `taskLocation` 为送达点。
5. 一次性扣除预计飞行耗电量。

### 4. 起飞时间

当前采用分配后立即出发的规则：

$$
t_{\text{start}}=\text{now},\qquad t_{\text{finish}}=\text{now}+T
$$

没有单独搜索最佳起飞时刻，也没有处理起降间隔和航路冲突。同一轮分配使用同一个 `now`。

## 六、空闲无人机的待命调度

### 1. 地图分块

采用根号分治的思想。

`mapX`、`mapY` 记录地图节点的最大横纵坐标。网格边长为：

$$
\text{blockX}=\max(1,\sqrt{\text{mapX}}),\qquad
\text{blockY}=\max(1,\sqrt{\text{mapY}})
$$

根据坐标除以网格边长得到区域下标。

### 2. 区域统计与评分

对每架没有接到订单的空闲无人机，统计：

- `q[i][j]`：该区域累计录入订单的取货点数量，包含已分配订单。
- `n[i][j]`：其他空闲无人机的当前位置，以及前往待命区域的无人机目标位置，落在该区域内的数量。
- `d`：当前无人机到区域代表节点的航路距离。

配送中和充电状态的无人机不计入 `n`。

排除不可达或到达后电量低于安全值的区域，再计算：

$$
g(i,k)=\alpha_gq_k+\frac{\beta_g}{1+n_k}+\frac{\gamma_g}{1+d_{ik}}
$$

选择最高分区域后，将状态改为 `TO_SPOT`，保存目标位置，扣除预计飞行耗电量，并设置：

$$
\text{doneTime}=\text{now}+\frac{d}{\text{DRONE\_SPEED}}
$$

每安排一架无人机，后续无人机会重新统计分布，因此能够将此前安排的无人机计入对应区域。

## 七、低电量与充电状态

采用原地充电、到时充满的简化模型，状态更新顺序如下：

1. 若无人机处于 `TO_CHARGE` 且充电结束时间已到，将电量设为 100，状态改为 `IDLE`。
2. 若配送或待命移动已结束，将位置更新为任务结束位置，状态改为 `IDLE`。
3. 若无人机处于 `IDLE` 且电量不高于安全值，开始充电并记录预计结束时间。

设当前电量为 $B$，每秒充电量为 $r$，则：

$$
T_{\text{charge}}=\frac{100-B}{r},\qquad
\text{doneTime}=\text{now}+T_{\text{charge}}
$$

`doneTime` 保存绝对结束时刻，因此计算时需要加上 `now`。

## 八、主要函数

| 函数 | 作用 |
| --- | --- |
| `getId()` | 为坐标分配或查询节点编号 |
| `mapInit()` | 读取航路并建立无向图 |
| `droneInit()` | 读取无人机信息 |
| `orderInit()` | 读取一条订单，生成编号并加入订单列表 |
| `h()` | 计算 A* 的欧几里得距离启发值 |
| `astar()` | 返回两点间航路距离，不可达时返回 `-1` |
| `getCurrentTime()` | 获取系统时钟的纪元秒数 |
| `main()` | 状态更新、订单分配和待命调度 |

## 九、输入与输出

### 输入格式

```text
航路数量
端点1_x 端点1_y 端点2_x 端点2_y 航路长度
……共 M 条

无人机数量
位置_x 位置_y 最大载重 剩余电量
……共 K 架

取货点_x 取货点_y 送达点_x 送达点_y 截止时间戳 货物重量
……每输入一条订单，触发一轮调度
```

地图距离按米、时间按秒理解。重量使用统一单位即可。

`getCurrentTime()` 使用 `system_clock` 的纪元秒数，常见环境下为 Unix 时间戳。因此截止时间也需要使用相同时间基准。

### 输出格式

分配订单：

```text
DRONE: 1-> ORDER: 2
```

前往待命区域：

```text
DRONE: 3-> SPOT: 0,1
```

充电：

```text
DRONE: 2 CHARGING.
```

`SPOT` 后是网格下标，不是目标点坐标。

## 十、存在的问题

- 贪心未必全局最优。
- 仅输入新订单时更新状态。
- 一次执行一个订单，不支持多单合送、配送中接单或待命途中改道。
- 当前采用原地充电。
- 权重尚未验证，指标尚未归一化。

后续可通过不同订单分布和无人机配置进行模拟，比较订单完成率、平均配送时间、总航程和总耗电量，再调整权重与分配策略。本文按源码逻辑说明，未提供运行实验或性能测试结果。
